# 톡토기 시스템 기획 명세

기준은 2026-11-17 설치본 `framework-r4`와 플레이 명세 v2.1이다. 논리 좌표는 960×560px이며 +x는 오른쪽, +y는 아래쪽이다.

Pico2D 재구현에서도 본문의 키·시간·좌표·물리·모션 수치를 유지한다. 입력 어댑터와 출력 교체, 새 수락 관문은 [재구현 명세](../Rebuild.md)를 따른다. 아래 현행 구현 기록을 재구현 완료로 해석하지 않는다.
차기 [Stage·Level 전환](../StageLevel.md)은 같은 월드에서 위치·속도·동작·입력을 유지한다. 아래 960×560은 표시 필드이며 확장 월드의 전체 경계가 아니다. 기존 단일 코스는 회귀 프로필로 보존한다.

## 1\. 상태와 입력

행동, 물리 지지, 진행 상태를 별도로 기록한다. 공중에서도 행동은 `Idle`일 수 있으며, 이때 속도와 중력을 계속 적용한다.

|상태|진입과 종료|
|-|-|
|`Idle`|기본 대기, 조준, 제자리 회전 표현. 접지 이동은 Walk, 준비가 승인되면 Jump, 적격 작업은 Interact/Combat으로 전이한다.|
|`Walk`|실제 수평 이동 거리로 보행 위상을 진행한다. 양쪽 방향 유지 시 Walk 의도는 0이다. 입력 해제나 제동에는 현재 위상의 정지 자세를 쓴다.|
|`Jump`|준비·발사·상승·정점·낙하·착지·회복. 발판 이탈에도 발사 없는 낙하가 시작된다. 무입력 착지 뒤에는 종료 자세를 유지한다.|
|`Interact`|E 단발, F 유지, G 유지. 조건 상실 또는 유효한 취소 시 미실행 효과를 닫고 필요한 복귀 자세를 표시한다.|
|`Combat`|X 공격 준비·활성·회복. 자연 종료 후 Idle. 피격과 착지 회복은 별도 시간으로 처리한다.|
|진행 상태|Playing에서 물리와 효과를 처리한다. Paused에서는 코스와 현재 표시 셀을 고정한다. Failed/Cleared에서는 새 행동·효과가 정지하고 종료 자세를 표시한다.|

키·장면별 조작과 DOWN/UP·검색·포커스 계약은 [Control](../Control.md#atlas-controls)을 따른다. 아래는 입력을 수락한 뒤의 게임 시간·물리·행동 규칙이다.

## 2\. 시간과 사건 순서

1. SDL2 이벤트의 시각과 입력 순번을 보존한다. 120Hz 틱 큐에 넣으며 화면 갱신 목표는 60fps다.
2. 활성 틱에서 전환 경계와 이동을 갱신하고, 접촉·발판 이탈·실패·위험 접촉을 확인한 뒤 행동 입력을 적용한다.
3. 이어서 발사·작업·타격·목표를 처리한다. 해당 틱에서 입력 문맥을 닫는 이벤트와 뒤에 대기한 입력은 틱 뒤에 처리한다.
4. 큰 프레임 간격에서 처리 한도에 남은 틱은 다음 갱신으로 넘긴다. 렌더링은 셀을 읽고 표시하며 발사·타격·소비를 확정하지 않는다.

자동 반복·중복 DOWN과 대응 없는 UP은 새 행동을 만들지 않는다. 좌·우 Shift를 함께 누르면 둘 다 해제할 때 제동을 해제한다. 포커스 상실은 활성 플레이를 일시정지하며, 장면 전환과 함께 유지 입력·대기 요청을 정리한다. 화면을 되돌아와도 중단된 작업의 효과를 재생하지 않는다.

## 3\. 보행·충돌·도약

|항목|현행 수치 및 경계 조건|
|-|-|
|보행|일반 24px/s, 회복 13.2px/s. 접지 목표 속도에 접근하는 가속은 760px/s², 무이동 감속은 1,200px/s², Shift 제동은 1,700px/s². 보행 주기 기준 480ms.|
|지형|수직 Capsule 반경 14px·높이 52px. 중력 850px/s², 최대 하강 속도 660px/s. 수평 스윕 뒤 수직을 처리한다.|
|유효 지지|하강 접촉 때 기준 x가 발판 범위 안에 있어야 착지한다. 둥근 모서리 바깥 접촉은 바깥쪽으로 빠지며, 천장은 상승을 멈춘다. 시작점·체크포인트는 지지발과 다른 고체의 여유를 검증한다.|
|일반 발사|기본 준비 80ms, 기준 상승 속도 426px/s. 승인 때의 방향·조준·수평 속도와 지지면을 보관한다. 발사 때 같은 지지가 유효해야 한다.|
|탄성 발사|탄성 잎 착지 전 100ms 이내의 Space UP을 다음 적격 착지에서 평가한다. 착지 후에는 같은 잎에서 165ms까지 허용한다. 기본 준비 45ms, 기준 상승 속도 541px/s.|
|예약 소비|발사하면 요청·탄성 입력·착지 보너스를 소비한다. 착지하면 선행 입력을 정리한다. 공중 추가 추진을 허용하지 않으며 준비 중 지지 상실은 발사 없는 낙하로 전환한다.|
|착지 회복|하강 충격 `>370px/s`는 강착지 270ms, 그 외는 190ms. 보행·재도약을 허용한다. 일반 회복 재도약은 추진 계수 0.82, 탄성 보너스에는 1.0을 적용한다.|
|착지 직후 연결|현재 착지 셀에서 즉시 재도약하면 표본·방향별 준비 트랙을 사용한다. 이때 발사까지의 대기는 트랙 길이를 따른다.|

```text
a = 위(+1) / 중립(0) / 아래(−1), d = 왼쪽(−1) / 오른쪽(+1)
p = 일반 회복 재도약이면 0.82, 그 외 1.0
vx = 승인 시 vx + d × (148 + (탄성이면 20, 아니면 0) − 29a) × p
vy = −(탄성이면 541, 아니면 426) × p − 21a
```

## 4\. 회전과 표시

* **지상 회전.** Q의 중립 반전은 480ms이며 서로 다른 지지 자세를 각 100ms 표시한다. Z 본편은 1.55초·62셀이다. 보행 중 진입에는 위상별 제동 자세를 연결한다.
* **지지 검사.** 회전 트랙이 요구하는 발끝의 x 좌표가 현재 발판 구간에 들어야 한다. 지지 부족 시 Q·Z는 거절한다. 방향키 반전은 모서리 자세로 안쪽에 이동해 지지가 확보되면 시작한다.
* **회전 중 입력.** 마지막 예약 작업 또는 도약을 회전 종료 경계에서 다시 평가한다. F·G 예약은 키를 계속 유지해야 한다. 새 Space DOWN·피격·지지 상실·장면 전환은 대기 요청을 정리한다.
* **공중 표현.** 전개 핵심 셀 100ms, 일반·탄성 공중제비 330ms 가운데 역위 105ms. 회복 재도약은 압축 표현을 쓴다. 착지·천장·피격은 공중제비를 중단한다. 이 회전은 Capsule 방향과 추진을 바꾸지 않는다.
* **표시 순서.** MotionSet이 상태에서 `(clip, view, sample)`을 고른다. Assets가 128px 5패스를 주고 SpriteRenderer가 추적 점광원·주변광으로 CPU 조명을 계산한다. Sprite Alpha·윤곽과 정수 확대 Nearest를 유지한다.
* **책임.** App은 입력/장면, FixedStepTimeline은 시간, Game은 행동·효과/진행, physics.py는 충돌, MotionSet은 모션, PlayView/Viewer는 표시를 맡는다.

## 5\. 검증과 범위

* 물리 검수는 지지 이탈·천장·착지 재도약, 탄성 창 안팎, 접지 Q/Z·모서리 반전, 일시정지·포커스 상실·짧은 DOWN/UP을 확인한다.
* 같은 입력에서 발사·소비·효과의 횟수와 시각을 비교한다. 현재 Q/Z의 저표시율 검수와 74개 회귀 그룹은 배포 기록을 참조한다.
* **검증·보류 구분.** 실기 표시 지연은 재구현 인수에서 측정한다. F2 Bloom은 차기 구현 범위이며 현행은 미구현이다. 동적 발판·경사 IK, 정확한 중간 저장 복원, 최종 생산 좌표 계약(DEC-06)은 계속 보류한다.
