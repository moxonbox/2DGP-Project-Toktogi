# 입력 지연·동시 입력·누락 진단 및 조치

2026-11-18. 063 이후 로컬 입력 경로를 먼저 재현하고 수정했다. Computer-Use·보이는 창은 사용하지 않았다.

## 확인한 문제와 조치

| 재현 | 수정 전 | 원인 및 수정 |
| --- | --- | --- |
| Ctrl+F → F 해제 → Enter → Ctrl+F | 두 번째 검색이 열리지 않음 | 검색 중 KEYUP이 viewer_keys에서 빠지지 않았다. 검색 상태와 관계없이 유효 KEYUP을 정리한다. |
| D DOWN 후 다른 키 이름의 동일 scancode UP | right가 계속 held로 남음 | 키 이름이 키맵에 있어야 해제 경로에 들어갔다. 저장된 물리 키가 있으면 이름이 달라도 해제한다. |
| 물리 D scancode + 다른 keysym | F9로 해석되어 이동 불가 | SDL 키 이름만 사용했다. scancode 이름으로 명령 키를 정하고 원래 키 이름은 Event.symbol에 보존한다. F2 Unicode 입력은 TEXTINPUT을 유지한다. |
| F 유지·공격 종료 후 X/E 공격 새 DOWN | 새 공격이 시작되지 않음 | 같은 논리 x를 이미 누른 것으로 합쳐 새 단발 입력까지 막았다. 물리 키의 새 DOWN마다 공격 적격성을 다시 검사한다. 활성 공격 중에는 중복 효과를 만들지 않는다. |
| 1ms D DOWN·4ms UP | 이동 변화 0 | 같은 120Hz 틱에 누름·해제가 상쇄됐다. 이동·조준·modifier 누름은 최소 한 물리 틱에 전달한다. 10~240fps 모두 0.052778px의 동일한 물리 변화가 확인됐다. |
| 프레임 시작 뒤 수집 도중 도착한 입력 | 다음 프레임으로 불필요 이월 | dt를 수집 전에 확정했다. 수집 종료까지의 시간을 해당 프레임 dt에 포함한다. 틱 경계·timestamp 순서는 유지한다. |
| 완전 조준에서 반대 방향 회전 요청 | 표시 각도 시작까지 175ms | 키 유실이 아닌 조준 중립 복귀 대기였다. 회전 진입 시 원본 중립 복귀를 2배속으로 재생해 측정 대기를 91.667ms로 줄였다. 조준값·이동 반응은 별도 즉시 처리한다. |
| 시작 4초 내 적격성 거절 | 사유 안내가 보이지 않음 | HUD가 초기 안내 외 알림을 가렸다. 새 행동 피드백을 바로 표시하고 다음 행동이 수락되면 이전 거절 안내를 정리한다. |

추가 경계 조건: scancode=0인 입력은 물리 식별자가 없는 것으로 보고 키 이름을 대체 식별자로 쓴다. 여러 키가 ID 0 하나로 합쳐지는 것을 방지했다.

## 동시 입력·수명 규칙

- 실제 유지 중인 방향 축 상태가 단기 누름 기록보다 우선한다. A+D·W+S 동시 유지는 중립이며 한쪽 해제 시 남은 방향에 반응한다.
- Ctrl·Shift의 좌우 물리 키를 따로 추적한다. 하나를 놓아도 다른 쪽이 눌려 있으면 논리 상태는 유지한다.
- Ctrl이 먼저 눌린 뒤 D와 함께 틱 안에서 해제되어도 그 조합을 한 틱에 전달한다. Ctrl+A/D 회전·이동 제동 규칙은 유지한다.
- 단발 공격은 F/X/E의 새 물리 DOWN을 수락·거절 판단한다. 반복 DOWN은 추가 공격을 만들지 않으며 유지 섭식·손질의 참조 수명은 바꾸지 않는다.
- Pause·포커스 상실·F2·R은 실제 held와 단기 누름 기록을 함께 정리한다. 합성 Space UP이나 유령 도약을 만들지 않는다.
- 복귀 뒤에는 새 DOWN이 필요하다. 공중·준비·피격·활성 공격·발 지지 부족으로 거절되는 행동은 입력 유실과 구분한다. 자동으로 쿨다운 뒤 실행되도록 버퍼링하지 않는다.
- A/D 180° 제한, W 임시 반원·S 기본 복귀, Ctrl 연속 회전·100ms 멈칫, W 아래/S 위 조준을 유지한다.

## 지연 측정

고정 물리는 120Hz다. 입력은 기존 계약대로 물리·접촉 처리 뒤 틱 경계에서 소비한다. 이동은 다음 물리 틱부터 반영하므로 논리 수락과 위치 변화 시각이 다르다.

아래는 프레임마다 16개 입력 시점을 주입한 합성 시계 검사다. `프레임 관찰`은 위치 변화가 있는 갱신을 처음 확인한 프레임 경계이며 실제 화면 픽셀·GPU present 측정이 아니다.

| 갱신 fps | 입력→틱 수락 최대 | 입력→물리 위치 변화 최대 | 입력→프레임 관찰 최대 |
| --- | --- | --- | --- |
| 10 | 7.292ms | 15.625ms | 103.125ms |
| 15 | 6.250ms | 14.583ms | 72.917ms |
| 30 | 7.292ms | 15.625ms | 40.625ms |
| 60 | 7.812ms | 16.146ms | 24.479ms |
| 120 | 8.073ms | 16.406ms | 16.406ms |
| 240 | 8.203ms | 16.536ms | 16.536ms |

- 이번 샘플은 모두 1틱(8.333ms) 안에 수락되고 2틱(16.667ms) 안에 물리 위치가 변했다. 프레임이 느리면 보이는 반응은 별도로 늦어질 수 있다.
- 60fps의 프레임 관찰 최대 24.479ms는 재현 조건의 결과이며 실측 input-to-photon 보장이 아니다. OS 큐 대기·키보드·모니터·실제 렌더 시간은 포함하지 않는다.
- 2초를 넘는 정지에는 240틱 한도 이후 누적 시간이 남아 후속 프레임으로 회수된다. 그 구간의 입력 지연은 이 표의 정상 프레임 범위 밖이다.
- 3ms 탭의 0.052778px는 입력 전달 증거다. 가속·픽셀 반올림 때문에 탭 한 번이 화면에서 1px 이동하는 것을 보장하지 않는다.
