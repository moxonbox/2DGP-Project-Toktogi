# 이슬의 길 · Habitat Stage r1

2026-11-18. Pico2D 후보 기본 프로필 `habitat`. 3,120×560 월드, 10개 발판, 3개 연속 Level.
실행: `toktogi/prototype_pico2d/Start-Toktogi.cmd`. 기존 시험은 `--profile pond_test`, 기존 연속 코스는 `--profile seamless`.

## 플레이 흐름

| 구간 | 주요 행동 | 공간·재질 | 진행 조건 |
| --- | --- | --- | --- |
| 젖은 숲바닥 | 보행, 제동, 섭식, 반전·360° 회전, 손질 | 넓은 젖은 통나무, 돌, 낙엽과 이끼 | 첫 등불 활성화, 첫 쉼터 저장 |
| 수면 잎길 | 짧은 도약, 탄성 연속 도약, 물고기 회피·반격 | 개구리밥 발판, 수면, 수초 실루엣 | 두 번째 등불 활성화, 두 번째 쉼터 저장 |
| 갈대숲 귀환 | 상승 도약, 가시 장애물 공격, 씨앗 수집 | 젖은 돌과 높은 잎, 갈대·부들 배경 | 세 등불 활성화 후 마지막 깃발에서 정지 |

- 등불 3개는 필수. 씨앗 3개, 섭식, 회전·손질은 선택 활동이다.
- 등불을 켰을 때 해당 쉼터 발판에 서 있으면 즉시 체크포인트가 저장된다. 재시작 시 선행 등불이 복원된다.
- 체크포인트 복원은 기존 규칙을 유지한다. 씨앗·먹이·행동 카운터는 다시 시작하므로 영구 수집 기록이 아니다.
- WASD 직접 회전(해제 시 현재 각도 유지), A/D 이동 72px/s(회복 39.6px/s), W/S 도약 조준, Space를 눌렀다 놓아 도약, Ctrl 제동, Shift 달리기(144px/s). 반대 입력 제동은 1,700px/s²다.
- E는 가까운 적 공격, 활성화·수집, 유지 섭식, 대상이 없을 때 유지 손질 순서다. F 공격과 X 호환키도 제공한다.
- 손질은 넓은 발판에서 왼쪽을 향해 E 유지. Q 반전, Z 지상 회전. 기존 접지·발 위치 조건을 따른다.
- 탄성 발판에는 작은 꺾쇠 표시를 둔다. 착지 직전 Space 입력과 착지 후 연결 창은 기존 물리를 따른다.
- C261은 x=1030~2110 수면 구간에서만 공격한다. 0.65초 물결 경고 후 위치를 고정해 입 돌출·도약 공격을 번갈아 수행한다.
- 수면 밖은 모션 연습·섭식·손질을 위한 안전 구간이다. 가시 장애물은 귀환 구간에 별도 배치한다.
- P/Esc 일시정지, R 체크포인트 재시작. 실패·일시정지·완료 안내와 구간별 행동 문구를 표시한다.

## 실제 에셋 연결

- A01 `plant_lemna_minor`: 개구리밥 발판. 원본 `frond_top` 앵커를 물리 발판 높이에 맞춘다.
- A02 `env_still_water`: 수면 타일. 월드 수면은 y=400이며 물결 장식은 게임 시간으로 움직인다.
- A03 `env_shore_slope`: 배경 기슭. 시각 장식이며 경사 충돌을 추가하지 않는다.
- A04 `env_wet_wood`: 통나무 발판, `walk_top` 앵커.
- A05 `env_wet_stone`: 돌 발판, `top_surface` 앵커.
- A06 `env_wet_leaf_litter`: 낙엽 배경, A07 `env_algae_patch`: 먹이 위치 표시. 먹이가 소진되면 이끼 표시도 사라진다.
- B04 물개구리밥, B05 붕어마름, B06 부들, B07 갈대: `background-r02` 번들에서 읽은 배경 실루엣.
- C011: 기존 기본·보조 모션 번들. C261: `gambusia-r03` male/right 6액션 72셀과 mouth_tip을 재사용한다.
- A 에셋은 `environment-r02` 명세·PNG SHA256·coverage·패스·앵커를 확인한다. B는 기존 서명/해시 검증 로더를 재사용한다.
- 그림 크기는 코스 가독성을 위한 일정 배율이며 Nearest를 적용한다. 접지 표시는 기존 수평 Capsule 발판이다.
- 현재 수면 잎은 개구리밥이다. 정식 연꽃잎 제작물이 없으므로 연꽃 리소스로 표시하지 않는다.

## 조명·머티리얼

- 기존 Sprite/Base/Normal/RM/Emissive 5패스 BRDF를 환경에도 사용한다. 크기가 다른 직사각형 셀은 자신의 좌표 격자를 만든다.
- Base의 sRGB 변환, 카메라 공간 Normal 정규화, RM의 roughness/metallic, Emissive 합성 및 원본 Alpha를 유지한다.
- 나무·돌·잎의 발판은 원본 패스를 일정 배율로 정렬한 뒤 광원 x 오프셋 -40/-20/0/20/40을 미리 계산한다.
- 게임 시간에 따른 같은 광원 단계가 환경 발판과 톡토기에 적용된다. 톡토기는 위치에 따른 실제 조명 계산을 계속 사용한다.
- 수면·기슭은 시작 시 정적 조명을 계산한다. B 실루엣은 원본 Sprite로 합성한다. 전 환경을 매 프레임 재조명하지 않는다.
- 등불 주변 광륜과 숲의 빛줄기는 시각 효과다. 톡토기의 Bloom은 기존 Emissive 전용 선형 합성을 사용한다.
- 그림자·발판·물고기·표식은 공통 월드 카메라로 이동한다. 환경 파일 읽기와 디코딩은 준비 단계에서 끝난다.
- 현재 계산은 Pillow CPU 경로이며 Pico2D/SDL이 출력한다. 새 GPU 픽셀 셰이더를 구현한 것으로 간주하지 않는다.

## 검증과 제한

- `verify_habitat.py`: 9개 인접 발판 간격의 실제 도약, 9개 E 상호작용, E 공격, 손질·회전, 체크포인트·클리어, 안전 구간 검사. 새 수면 높이에서 물고기 피격·회피 4건도 확인한다.
- 세 구간 프레임에서 파일 읽기 0회와 게임 상태 불변을 확인한다. 직사각형 재질 광원 반응과 캐시 조명 프레임 차이를 검사한다.
- 실행 결과와 화면은 `toktogi/prototype_pico2d/habitat_artifacts/`에 기록한다.
- 최적화 후 동일 Windows/direct3d 180프레임 렌더 p95는 플레이 24.83→15.39ms, F2 광원·Bloom 21.33→16.69ms다. 준비·물리·입력 폴링은 제외하며 장치 전체 60fps 인수가 아니다.
- 품질 기준 RGBA 이미지 24개 차이 0. coverage/Bloom 계산 영역 축소, HUD 재사용, 화면 복사 절감만 적용했다. 캐시 상한·해상도·광원 식·모션 프레임을 유지한다.
- 최고 속도 100ms, 정지 66.67ms, 역방향 시작 50ms(120Hz 시뮬레이션). 9개 인접 도약과 상호작용을 재확인했다. 근거는 `optimization_results.json`.
- 플레이/F2 최대 프레임은 25.44/43.50ms이며 F2 p95는 정확한 60Hz 예산을 0.027ms 초과한다. 장시간 실기 인수는 남아 있다.
- 기존 물고기 회피·반격과 체크포인트 회귀를 별도 확인한다. 전체 회귀·Computer-Use는 수행하지 않는다.
- 경사/동적 IK, 수영·부력, 새로운 생물 모션, 제작 에셋의 DEC-06·양산 보류는 이번 변경에 포함하지 않는다.
