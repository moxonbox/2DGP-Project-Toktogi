설계 명세

초기화, 입력과 시뮬레이션, 플레이 렌더링, F2 검수의 호출 순서입니다. 심볼을 선택하면 Python 파일 구조로 이동합니다.

실행과 초기화

  1. App.__init__ L34

    main.py에서 시작한다. 창을 열고 Assets·Game·PlayView·Viewer·입력 객체를 생성한다.

  2. Assets.load L31

    원본·보조 ZIP의 해시, 호환 서명, 프레임을 검사한다. Track을 만들고 SpriteRenderer에 맵 제공 함수를 넘긴다.

  3. Game.__init__ L19

    플레이에 필요한 에셋을 검사한다. MotionSet을 만들고 Course의 시작점·체크포인트를 검증한다.

  4. App.run L172

    표시 루프를 60fps 목표로 돌린다. 종료 시 Assets를 닫고 Pygame을 종료한다.

이벤트와 120Hz 시뮬레이션

  1. EventClock.events L22

    SDL2 큐 시각을 Pygame 이벤트에 대응시킨다. App이 이를 시작 시각 기준으로 바꿔 틱 큐에 넣는다.

  2. FixedStepTimeline.advance L29

    큐를 시각·입력 순번으로 처리한다. 누적 시간만큼 1/120초 틱을 실행하고 남은 시간을 보존한다.

  3. Game.step L532

    전환·이동·충돌·위험을 먼저 갱신한다. 활성 플레이에서는 입력 콜백을 실행한 뒤 발사·작업 효과·목표 조건을 판정한다.

  4. App._event L90

    게임 키를 Game.edge에 전달한다. 틱 이후 처리되는 장면 전환과 포커스·중복 키 처리도 맡는다.

플레이 렌더링

  1. PlayView.draw L36

    코스와 캐릭터 위치를 읽고 추적 광원을 잡는다. Game.visual()로 현재 셀을 요청한다.

  2. MotionSet.cell L226

    상태·방향·경과 시간으로 Track의 (clip, view, sample) 키를 고른다.

  3. SpriteRenderer.render L23

    Assets의 5패스 맵을 사용한다. 조명 모드에서는 스프라이트에 대한 상대 광원 위치로 계산하거나 캐시에서 가져온다.

  4. shade L33

    Normal·RM·Emissive를 CPU에서 평가해 Sprite Alpha를 유지한 Surface의 픽셀을 만든다. App.draw에서 창을 갱신한다.

F2 검수와 기록 재생

  1. App.switch L56

    입력 상태를 정리하고 장면을 바꾼다. F2에서는 FixedStepTimeline이 Viewer.step을 호출한다.

  2. Viewer.draw L177

    같은 Assets를 사용해 선택한 모션과 맵·조명·마커를 표시한다.

  3. game_replays L11

    독립 Game에 기록 입력을 넣어 셀과 사건 시각을 계산한다. HTML 생성 시에는 매 틱의 위치·속도·지지면도 기록한다.

  4. build_motion_preview.py

    모션·실제 게임 시간표·리플레이를 스프라이트와 함께 단일 HTML로 내보낸다.

완주 흐름

첫 발판에서 위로 도약해 중간 등불을 켠다. 탄성 잎으로 높은 발판에 오르고 목표 영역에서 충분히 느린 상태를 0.20초 유지한다. 가시 껍질은 피하거나 X로 제거할 수 있다.

C와 V는 플레이에서 미할당이다. 플레이 화면에는 키 안내 HUD가 없다.

상태 머신

행동 5개 · 진행 4개

행동 상태는 입력과 물리 사건이 바꿉니다. 아래 상태를 선택하면 다음 상태와 조건을 볼 수 있습니다. 현행 상태 원문

Idle · 대기

조준이나 제자리 회전 자세를 표시할 수 있다.

  • 유효 지지에서 ← / → → Walk
  • Space 뗌과 도약 승인 → Jump
  • E / F / G의 대상 및 지지 적격 → Interact
  • 적격한 X → Combat

물리와 게임 입력을 처리한다.

Paused

Cleared

Q와 Z는 시각 전환 슬롯을 사용한다. 회전 중 작업과 도약은 종료 경계에 대기할 수 있다. Space를 누르면 미발사 요청을 취소한다. 피격은 작업과 도약 준비를 끊고 넉백을 적용한다.

재질·조명 구조

공통 피벗 · 5패스

Blender 출력과 런타임 셀은 좌표와 피벗을 공유합니다. 플레이와 F2가 같은 5패스를 읽어 색을 계산합니다.

Sprite

베이크된 색과 윤곽, 최종 실루엣 Alpha.

Base

sRGB 표면색과 표면 coverage.

Normal

카메라 기준 표면 방향. RGB를 벡터로 디코드.

RM

R은 Roughness, G는 Metallic. 선형 값.

Emissive

선형 발광값. 눈 하이라이트 표현에 사용.

Blender → 패킹 → Assets → SpriteRenderer → 화면
CPU 조명은 Base를 선형화하고 Normal·RM·Emissive와 합성한다. Sprite의 Alpha와 윤곽을 보존한다. 게임은 상단 추적광과 주변광을 사용하며, F2는 고정·마우스·이동 광원을 지원한다.
