# 에셋 제작 파이프라인

2026-11-17 · v2.3 · 캐릭터·소품·배경·효과에 적용한다. 외형 명세, GPT Image 시트, Blender MCP 제작, 2D 출력, 게임 연결의 근거와 산출물을 연결한다.
폴더·ID는 [에셋 번호 규칙](AssetLabelRule.txt), 상대 크기는 [AssetSize](AssetSize.md), 런타임 이식은 [Pico2D 재구현](Rebuild.md)을 따른다. C011의 수치는 다른 에셋의 공통 규격으로 강제하지 않는다.

## 1. 대조 결과와 기준 문서

- 이번 기준은 이 채팅의 수정 요구, A=[C011 최종 에셋](../../asset/C/C011_toktogi/ASSET_INDEX.md), B=[제작 작업 폴더](../../../../../../Documents/ChatGPT/2DGP/)의 스크립트·시트다. [대조 기록](../../../../../../Documents/ChatGPT/2DGP/pipeline_production_review/production_evidence.json)에 원본 해시·검사 범위·한계를 남겼다. 파일 수정 시각만으로 최신본을 고르지 않는다.
- 보완한 누락은 팔레트 값·적용 순서·예외, 약한 웨더링의 조정 이력, 저면수 조형·접합·숨은 면, 눈의 크기별 강조, UV 보간과 화면 필터의 구분이다. Emissive 저장 Alpha 설명도 실제 출력에 맞췄다.
- 범위·우선순위는 [통합 기획](game-design/001_toktogi_game_design_spec.md), 입력·물리는 [시스템](game-design/011_toktogi_system_design_spec.md), 등장·상호작용은 [콘텐츠](game-design/012_toktogi_content_design_spec.md), 타격은 [전투](game-design/013_toktogi_combat_design_spec.md)를 참조한다.
- 리그·패스·요구 ID는 [플레이 v2.1](game-design/022_toktogi_playable_action_animation_spec.md), 모듈 책임은 [프레임워크](game-design/021_toktogi_game_framework_spec.md), 차기 실행은 [Rebuild](Rebuild.md)가 기준이다. 생물 자료·과거 프롬프트는 근거이며 현행 채택 범위를 자동 확장하지 않는다.
- 요구 ID·revision·출처·측정 조건·구현/검수/보류/제외·검증 파일을 연결한다. 요청한 수치·스크립트 설정·출력 실측·과거 검증을 구분하고 상충 값은 결정 사유를 남긴다. 문서 작성·제작·게임 검증 완료는 별도 상태다.
- 번호 규칙의 자리 수·종류 2·확장자 불일치는 §3, 크기·신규 로더·배포는 §7·10·11에서 관리한다. 본 문서의 실행 경로는 `../../toktogi/prototype/`, 기획 경로는 `game-design/`다. 참고 문서의 옛 경로를 복사하지 않는다.

## 2. 에셋별 입력 명세와 제작 계약

- 신규 에셋은 `document/<에셋명>_model.md`에 종·단계·실루엣·기관 수·부착 위치·색·표면·미정 값을 기록한다. 생물 사실과 귀여운 비율·생략·과장 같은 게임 각색을 구분한다.
- 동작은 `<에셋명>_movement.md`와 게임 기획에서 정한다. 플레이/검수 전용/보류/제외, 모션·전환·지원 방향·접지·작업·타격 마커와 효과 소유자를 명시한다.
- 에셋 ID·variation·revision, 표시 크기·배율·카메라·축·단위·피벗·여백, 삼각형·본·텍스처·셀·메모리 예산, 기준 장치·표시율·허용 오차를 정한다. 팔레트 색/역할·적용 재질/패스·예외·명암 단계·필터·디더·조명 프로필도 제작 계약에 포함한다.
- 생물 체장·부속기관 포함 외접 크기·Blender 단위·타일/화면 px·충돌체 크기를 구분한다. 다른 에셋과 비교할 때 같은 측정 부위·기준 개체를 사용하고 셀 크기만으로 실제 체장 배율을 정하지 않는다.
- 관련 문서·사진·시트·스크립트·도구 버전·산출물의 상대 경로와 해시를 색인 또는 manifest에 연결한다. 외부 출처·라이선스/게임 재배포 가능 범위, 스타일 기준 revision·참조 포즈·카메라/조명·모션 설정과 근거 있는 차이도 기록한다.
- 정적 소품·배경은 이미지·재질·배치 피벗부터, 효과·2D 전용은 프레임·시간·합성·Alpha부터 정한다. 3D·리깅·재조명·충돌은 실제 용도가 요구할 때 적용한다.

## 3. 번호·폴더·파일 식별 계약

- [AssetLabelRule](AssetLabelRule.txt)의 분류는 A 일반·B 배경·C 캐릭터/관련·D 데이터/UI·E 효과다. 상단 트리의 A–C 예시는 전체 목록이 아니다. 분류만으로 리그·모션·재조명 제작을 의무화하지 않는다.
- 규칙의 “비트”는 16진수 자리로 해석한다. 7..0은 8자리지만 밑줄/idle 예시 길이가 불일치하며 종류 `2`는 미정이다. 확정 전에는 기존 C011·C2xx 경로를 유지하고 C2xx를 `3=Enemy`로 자동 변환하지 않는다.
- 명세의 자리 의미는 7=분류, 6=종류, 5=에셋, 4=외형 variation, 3=모션 variation, 2..0=프레임이다. 자리당 용량·프레임 시작 번호·방향/패스 배정·충돌/초과 처리는 번호 규칙에서 확정한 뒤 적용한다. 잘라내기·순환 재사용으로 ID를 만들지 않는다.
- 폴더 ID·논리 asset_id·외형 variation·클립·view·sample·pass·revision을 별도로 대응시킨다. C011 폴더와 `toktogi_player` manifest ID, C211의 `paradosa` 경로와 `pardosa` 생물/명세 ID를 동일 문자열로 가정하지 않는다. `_`와 기존 철자를 보존한다.
- 기본 배치는 `asset/<분류>/<ID_이름>/{3D,2D,document,sheet}`와 `ASSET_INDEX.md`다. C 에셋의 모션 HTML은 에셋 루트에 둔다. 실제 Blender 확장자는 `.blend`이며 규칙의 `.blender` 표기와 구분한다. FBX는 인계 요구가 있을 때 생성한다.
- 현행 프레임은 `2D/<계열>/<모션 ID>/<view>/<frame>.png`다. 예: `2D/aim/aim_down/<view>/...`; 5패스는 파일 내부 적층이므로 패스별 프레임으로 중복 집계하지 않는다. `2D/integrated-r5/`의 제작 아틀라스·manifest는 별도 원본 계열이다.
- 파일명은 모션/뷰/표본 키와 충돌 없이 매핑하고 프레임 순서는 manifest로 읽는다. `predator_`가 남은 생물 문서·논리 ID는 제거된 폴더 접두사와 별도 매핑하며 전역 치환하지 않는다. 신규 번호 미확정 시 임시 문자열 키와 보류 사유를 색인에 남긴다.
- `3D/versions`는 비중복 이전 파일을 7z에 보관하고 `restore_map`에 archive/current·상대 경로·SHA256을 기록한다. 별도 작업 폴더에서 복원·해시 확인 후에만 중복을 정리하며 최신 출력의 출처를 잃지 않는다.

## 5. GPT Image로 3D 제작용 2D 시트 생성

1. `<에셋명>_model.md`와 §4의 C011 표시용 참조 이미지·가능한 3D 기준 렌더를 GPT Image에 함께 전달한다. 공통 조형·표면·색 대비와 종별 기관·개수·비율, 생략·과장·미정 값을 프롬프트에 명시한다. 5패스 적층 PNG는 패스 용도를 확인해 표시용 영역을 참조한다.
2. 정면·양측면·후면·상면과 필요한 배면·기관 확대도를 생성한다. 동일 개체·비율·크기·중립 자세, 원근 왜곡이 적은 시점, 명확한 실루엣과 서로 겹치지 않는 패널을 요구한다. 치수는 명세의 기준점으로 정하며 생성 이미지의 픽셀 길이를 생물 실측으로 쓰지 않는다.
3. 균일한 조명·단순한 배경으로 형태와 기본색을 읽게 한다. 하이라이트·투영 그림자·원근·패널 글자를 실제 무늬나 지오메트리로 모델링하지 않는다. 패널 이름은 개체 밖에 둔다.
4. 시점마다 기관 수·부착점·눈·무늬·접지 높이를 대조한다. 불일치는 GPT Image 부분 편집 또는 명세 수정으로 해결하며 생성 그림의 임의 구조를 생물학적 근거로 확정하지 않는다.
5. 통과본은 `sheet/<에셋명>_sheet_r01.png`처럼 보관한다. 프롬프트, 입력 명세 revision·참조 이미지, 도구/모델명·생성일, 편집 이력·선택 이유·미해결 부위를 색인에 기록한다. 제공되지 않은 seed 등은 추정하지 않는다.
6. 시트를 실제 표시 크기로 확인하고 C011과 나란히 실루엣·기관 분리·색 대비·디테일 밀도를 검수한다. 시트 파일·해시·패널 방향·기준 길이·스타일 설정을 전달한다. 신규 제작의 시트→모델 절차와 기존 모델→참조 시트 절차를 구별하며 C011의 후속 시트 이력은 §12를 따른다.

## 6. Blender MCP 모델링·UV·리깅

1. MCP 연결과 대상 파일·장면·컬렉션을 확인하고 작업 사본을 만든다. 검수한 시트를 참조 이미지로 배치해 축·단위·기준 길이를 맞춘 뒤 편집 가능한 메시를 생성한다. 이미지를 평면에 붙인 결과로 대체하지 않는다.
2. C011은 구 대신 Round Cube 기반 둥근 덩어리, 목 없는 머리–몸, 짧고 두꺼운 다리·더듬이로 각색한다. 눈 돌출 30% 감소는 당시 버전 대비 요청값이다. ‘큰 눈 하나’ 요청과 현행 좌우의 둥근 눈 배치를 구별해 기록하고 임의로 외눈 구조로 바꾸지 않는다. 종별 기관 수·가려진 구조·furca 분지/접힘은 외형·행동 자료와 대조한다.
3. 에셋별 예산을 실측한다. C011 목표 약 3,000삼각형과 기존 기본 개체 2,732를 구분한다. 더듬이 팔각·다리 육각 단면은 감축 예시이며 전 부위 적용 사실로 단정하지 않는다. 변형 후 평가 메시·본·소품을 따로 집계하고 숨은 눈/몸 내부 면은 모든 지원 포즈·시점에서 비노출일 때 제거한다.
4. 기존 UV·리그·머티리얼 구조를 유지하는 비율 수정은 대응표와 해시를 남긴다. UV는 보이지 않는 쪽의 최소 seam과 왜곡 균형을 택하고 체크 타일로 늘어짐·뒤집힘·겹침·밀도를 검사한다. 의도한 미러/반복과 비대칭 무늬를 기록하며 섬 여백·경계 색 번짐·슬롯·상대 참조/패킹을 정리한다.
5. 기준 자세·본 계층·Root·IK·weight paint를 구성한다. 관절 연속성, 몸–furca 접합의 틈·Normal·스무딩·관통, 미할당/오할당 웨이트·관절 붕괴·비균일 스케일을 검사한다. 접지발/작업발을 구별하고 게임 위치·충돌은 시뮬레이션, 리그 오프셋은 시각 표현이 소유한다.
6. Action 슬롯·선택기·NLA·IK 초기값을 명시한다. 저장본을 재개방해 정순·역순·임의 seek 후 같은 포즈가 나오는지 확인한다. 베이크 재생과 편집용 IK를 동시에 적용하지 않는다. 비율·토폴로지 변경 시 UV·웨이트·마커·공유 자세를 함께 재검사한다.
7. MCP 코드·내장/외부 선택기·출력기와 도구 버전을 보존한다. Blend·텍스처를 저장하고 packed 이미지와 외부 파일의 일치·누락 참조를 검사한다. FBX가 필요하면 축·스케일·웨이트·Action 왕복 검사를 한다. Computer-Use는 사용하지 않는다.

## 7. 생물 크기에서 제작·표시 크기로 변환

- [AssetSize](AssetSize.md)의 기준은 S. aquaticus **암컷 성체 최대 약 1.0mm**다. 평균값이 아니며 `길이비 = 선택한 체장(mm) / 1.0`으로 계산한다. 성별·단계·종/분류 수준·날개형·출처·범위·measure_kind를 보존한다.
- 몸길이·다리/더듬이 포함 외접치수·SL·TL·SVL·IL을 구별한다. 속/과 사례는 종을 선택해야 확정된다. 무시형 성체를 유체로, 응애 IL 1.1448mm를 전체 체장으로 취급하지 않는다. 미측정 값은 null, 연출 가정은 별도 값으로 남긴다.
- 실측 재현은 선언한 `1BU=1m`에서 `목표 길이(BU)=체장(mm)×0.001`이다. C011은 Metric·Unit Scale 1이지만 생물 mm↔BU 대응은 미확정이다. 화면용 상대 연출과 실측 단위를 섞지 않는다.
- C011 상대 연출은 `목표 체장(BU)=0.965396×생물 길이비×연출 계수`, `전체 배율=목표 체장/현재 등가 체장`으로 정한다. 0.965396은 idle/left f1의 Body/Head 우세 웨이트·몸 재질 정점 778개 X 범위인 대용값이다. 새 에셋의 앞/뒤 기준점·축을 정하고 웨이트/재질 변경 시 재측정한다.
- C011의 rest 전체 외접 1.207×0.864×0.825BU와 idle 평가 외접 1.172×0.871×0.873BU는 부속 기관을 포함한다. 체장비로 체폭·체고·기관 길이·충돌·질량을 자동 계산하지 않는다. 생물 길이비 6의 약 5.79BU는 계산 예시다.
- C011 카메라 평면 환산은 `1.78/128=0.01390625BU/px`다. 몸의 3D 축 길이는 시점·포즈에 따라 다르게 투영되므로 모든 방향·극단 자세의 Sprite/Base 외접치수를 실제 출력에서 측정한다.
- 크기 변경은 리그 전체·Root/IK 목표·소켓을 함께 갱신하고 이중 스케일을 검사한다. 카메라·셀·피벗·게임 배율·마커·접촉 오차를 같은 revision으로 맞추며 큰 생물을 무조건 128px에 맞춰 같은 몸 크기로 축소하지 않는다.
- C011 idle 좌/우 Sprite는 93×71/92×59px, Base는 89×67/88×55px다. 원본 최소 여백 3px와 보조 2px를 구분하며 새 에셋은 윤곽·발광 여유와 최대 자세 범위를 포함해 합격 여백을 사전 지정한다.
- 현행 C011은 논리 필드 960×560에서 셀 1×, F2는 1×/2×/3×다. Capsule 반경 14px·전체 높이 52px와 발 기준 위치는 시각 외접치수와 별도다. 새 객체의 이동 충돌·피격·타격·작업 범위는 게임 기획으로 정한다.
- 인계 기록은 생물 기준/연출 계수, 모델 기준점 길이·외접값, 카메라·BU/px·표시 배율, 뷰별 Sprite/Base 범위·피벗/마커·여백, 충돌 프로필과 표본/스크립트 경로를 포함한다.

## 8. 카툰·팔레트·2D 출력 계약

- 3D 몸 `NPR_Toon`·눈 발광, CPU 표면 평가 Sprite, 게임의 연속 CPU 재조명은 별도 표현이다. 장식 하이라이트와 광원 반사를 구별하고 Base에 조명/AO를 중복 굽지 않는다. [기술 검토](3Dconv2D.md)
- C011의 [1024² 기본색](../../asset/C/C011_toktogi/3D/textures/toktogi_rigged_basecolor.png)은 약한 UV 고정 무늬의 기준이다. 균일 기본색→무늬 추가→고정 광원/회색조 비교→128px 순서로 대비를 정한다. 검은 때·미세 노이즈로 얼굴/접점을 가리지 않으며 무늬의 프레임별 랜덤 재생성을 금지한다.
- 최종 [내장 출력기 사본](../../../../../../Documents/ChatGPT/2DGP/pipeline_production_review/embedded/TOKTOGI_SURFACE.py)은 픽셀 중심 1회 표면 판정→UV 기본색의 선형 공간 bilinear 보간→4단 명암→sRGB 변환→몸 팔레트 양자화→접촉 강조→외곽선 순서다. UV 보간은 화면 확대 Nearest와 다르며 UV 반복 경계·색관리의 이중 감마를 검수한다.
- C011 몸 팔레트(sRGB 13색): `#151C26 #273443 #435361 #5C6B78 #758592 #8E9DA7 #A6B1B7 #BCC5C8 #CED4D2 #E8E8DE #F3F1E6 #FBF8EF #FFFFFF`. 8bit RGB 제곱 차에 가중치 `(0.25,0.60,0.15)`를 주어 가장 가까운 색을 고른다. 자동 팔레트 재추출·디더는 기본 적용하지 않는다.
- 명암은 카메라 공간 Normal과 벡터 `(-0.36,0.57,0.73)`의 내적을 `[0,1]`로 제한하고 경계 `0.14/0.42/0.72`로 나눈다. 선형 RGB 배율은 `(0.36,0.42,0.51) / (0.53,0.60,0.66) / (0.73,0.77,0.80) / (0.95,0.95,0.92)`다. 다른 종은 색상 역할·명암 리듬을 맞추고 고유 팔레트와 변경 근거를 기록한다.
- 팔레트는 몸의 Sprite 명암에 적용한다. 눈·소품, 이후 더듬이 내부선/누름 접점 강조, 외곽선은 예외다. Base/Normal/RM/Emissive·게임 재조명 전체에 13색을 강제하지 않는다. 최종 가시 Sprite 색 737종은 예외를 포함한 값이며 색 수만으로 양자화 실패를 판정하지 않는다.
- 눈 강조는 UV에 고정하고 가시 눈 면적에 따라 부드러운 작은 강조와 큰 강조를 연속 보간한다. 작은 개체에 항상 흰 점 1px을 찍지 않으며 각도·가림·확대율·전환에서 점멸/눈 면적 대비 과발광을 검사한다. Base의 검은 눈과 Emissive·별도 강도를 구분한다.
- 외곽선은 coverage를 정수 오프셋 `dx²+dy²≤5`, 축 ±2px로 확장하고 `#22313B`로 채운다. 둘러싸인 1–2px 구멍 보정은 Sprite만 적용한다. AA·mipmap·임의 trim/회전·손실 압축을 기본 사용하지 않으며 정수 확대 Nearest, straight Alpha와 실제 배경 합성으로 테두리/유령 픽셀을 검사한다.
- 작은 접점 보정은 셀·좌표·패스·강도·사유를 기록한다. C011 `antenna_edge`·`press_accent`는 표시 보정이며 [게임 contact_ink](../../toktogi/prototype/materials.py)의 별도 셀/좌표 보정과 비교한다. 표면 수정이 필요하면 coverage·재질·마커도 갱신하고 표시 보정으로 관통을 숨기지 않는다.
- 모든 패스는 카메라·포즈·피벗·방향·크롭·샘플을 공유한다. C011은 128×128px, 피벗 (64,88), 직교 배율 1.78, 아틀라스 패딩 2px이며 셀 투명 여백은 별도다. `mirror_allowed=false`, 8개 순환 yaw와 호환 `right`를 구분한다. `right`는 `yaw_180`의 별칭이 아니다.
- 개별 PNG는 128×640px에 아래 5패스를 순서대로 적층한다. 아틀라스는 뷰·패스별 파일과 manifest rect로 읽는다. 생성 시트·미리보기 APNG·적층 PNG·런타임 ZIP을 혼용하지 않는다.

| --- | --- |

## 9. 모션·접촉·시간 검수

- 중립·idle·이동·대표 동작·복귀부터 만든다. C011 원본 idle 1.6초·8표본은 리듬 비교 기준이다. 새 idle의 주기·진폭·부속기관 위상은 종별 제작값으로 정하고 지지발 고정, 몸·머리·기관의 잔동작과 강조 순서를 기록한다.
- idle 루프의 끝/시작 자세·속도·눈 하이라이트·피벗을 비교하고 중복 끝셀의 홀드를 확인한다. 준비·핵심·복귀·취소의 경계를 공유하며 제작/게임 시간을 따로 기록한다. C011 공중제비 680/330ms처럼 표시 시간과 효과 시점을 각각 관리한다.
- 출력 키뿐 아니라 키 사이 자세에서 작업 접촉·지지발 높이/미끄럼·관절 교차를 검사한다. 의도한 접합, 실제 관통, 카메라에서만 겹치는 투영을 구분하고 검사 간격·객체 쌍·프레임·허용 오차를 남긴다.
- C011의 06 작업발 접촉 시 더듬이 굽힘·해제 복귀, 06–07 공유 자세·4발에서 오른쪽 3발 지지, 07 복귀·08 방울 이탈, Z 재디딤을 검수한다. 접촉을 없애 교차 수치만 낮추지 않는다.
- 방향 반전·보행 제동·섭식 복귀·공격 진입·착지 재도약·공중제비의 연결 셀과 중단 경계를 확인한다. Root 이동이 포함된 관찰 `obs_jump`를 게임 도약에 그대로 중복 적용하지 않는다.
- 실제 게임 배율과 C011의 128px 기준에서 10/15/20/30/60fps·시작 위상별로 핵심 포즈·접촉·하이라이트를 비교한다. 순간 자세 누락은 표본 배치·홀드·진폭에서 보완한다. 효과는 시뮬레이션이 실행하며 동일 입력의 Game/F2/HTML 시간표와 효과 횟수를 재검사한다.

## 10. 실행 연결·데이터·성능 검증

- 현행 [로더](../../toktogi/prototype/materials.py)·[패커](../../toktogi/prototype/pack_assets.py)는 integrated-r5·128px와 C011 필수 모션에 의존한다. 신규 에셋은 지원 셀/패스·상태/모션 바인딩·마커·시간표·충돌 프로필을 연결하고 별도 번들로 검증한 뒤 게임 사용 가능으로 표시한다.
- manifest/잠금에는 해당 형식의 schema·revision·기반 서명·원본/파일 해시를 맞춘다. 중복 셀 키, 누락 패스/뷰/표본, 경계 밖 rect, 비유한 좌표·0 이하 시간, 잘못된 마커 참조·전환을 검출한다. 손상·미지원 입력은 파일과 셀 키를 알려 실패시키며 idle로 숨기지 않는다.
- [MotionSet](../../toktogi/prototype/motion.py)의 게임 시간과 제작 표본 시간을 구분한다. 120Hz 시뮬레이션·표시 목표 60fps, 취소·세대·효과 1회 규칙을 유지한다. 같은 입력으로 Game/F2/HTML의 셀·마커·발사/작업/타격 시점과 종료 상태를 비교한다.
- 새 좌표/뷰는 [Pico2DBackend](Pico2DBackend.md)의 논리 좌상단→Pico2D 변환에 맞춘다. y축 차이만으로 Normal G를 뒤집거나 yaw를 중복 적용하지 않는다. 미러·이미지 회전은 리그 방향 출력을 대체하지 않는다. [StageLevel](StageLevel.md)의 level/stage 경계에서도 세계 px 배율·피벗·광원·모션 시간을 유지한다.
- 메모리는 고유 셀 수×패스 수×폭×높이×4byte의 RGBA 원본과 디코딩·셰이딩 캐시·업로드 텍스처·후처리 여유를 합산한다. ZIP 용량만으로 판정하지 않는다. 캐시 재사용에는 에셋/revision·셀·광원·재질·Normal/발광 모드의 관련 키를 반영한다.
- 기준 장치에서 로딩/워밍업과 120프레임 p95·최대 비용을 구분하고 CPU 계산·업로드·합성을 포함해 16.7ms 표시 예산을 검수한다. F2 Bloom은 [2Dshader](2Dshader.md)의 발광 전용 입력·6px 여유·피벗 유지·음성 대조를 따른다. Pico2D·Normal 비교·Bloom은 현재 구현 완료로 표시하지 않는다.

| 동작·시간 변경 | 영향 클립·루프·공유 경계·취소 복귀·게임 시간표·효과 시점을 함께 갱신한다. 후보 교차 개수만으로 통과 판정하지 않는다. |
| 색·윤곽·물성 변경 | 팔레트 버전·역할/예외·양자화/명암/무늬 설정과 출력기 해시를 기록한다. 같은 광원·뷰·표본의 전후 색상/회색조·1× 재생으로 무늬·접점·coverage·밝기 튐을 검사한다. Normal 원본/평탄·Emissive·Bloom은 [셰이더 명세](2Dshader.md)를 따른다. |
| 패킹·배포 | 개별 PNG 변경은 아틀라스·manifest·ZIP까지 같은 revision으로 갱신한다. ID/revision·파일 해시·뷰/셀/패스·피벗/마커·시간·전환, ZIP 잠금과 기본/보조 서명을 검증한다. 새 묶음을 별도 경로에서 열고 이전 묶음·복원 지도를 보존한다. 파일 이름/경로 변경은 색인·manifest·도구 기본값·HTML 링크까지 갱신한 뒤 전환한다. |
| 게임 연결·스타일 합격 | 같은 프레임에 C011과 새 에셋을 배치해 실제 배율·주변 환경·고정/이동 광원에서 비교한다. idle 루프·행동 진입/복귀 영상을 남기고 눈/기관 소실·밝기 튐·발 미끄럼·위치 도약은 보완한다. 로더·상태·캐시·효과는 해당 revision으로 검증한다. |
| 인수 기록 | 요구별 기대/실제·재현 입력·표본·허용 오차·이미지/로그 상대 경로·해시·검수일을 남긴다. 잔여 교차·미확정 번호·미검증 장치는 보류 사유와 다음 확인 단계로 기록하며 전 항목 합격으로 요약하지 않는다. |

## 12. C011 적용 사실과 재현 절차

- 외형의 생물 근거는 [toktogi_model.md](reference/toktogi_model.md), 게임 각색 이력은 §4·6이다. 기존 [원본 검증](../../asset/C/C011_toktogi/2D/integrated-r5/asset_validation.json)의 2,732삼각형·37본·최소 여백 3px·지지 높이 최대 약 0.364px는 새 측정값이 아니다. 보조 여백은 [AssetSize](AssetSize.md)의 2px와 구분한다. 다른 에셋에 C011의 기관·예산을 강제하지 않는다.
- [기본 manifest](../../asset/C/C011_toktogi/2D/integrated-r5/playable_manifest.json)는 82클립·1,444셀, [보조 manifest](../../asset/C/C011_toktogi/3D/framework-r4/runtime_poses.json)는 146프로필·930셀이다. [통합 Blend](../../asset/C/C011_toktogi/3D/toktogi_unified.blend)는 편집용이며 기존 출력의 출처·해시를 소급 바꾸지 않는다.
- [에셋 색인](../../asset/C/C011_toktogi/ASSET_INDEX.md)에 원본·실행 상태를 연결한다. 이전 자료는 [복원 지도](../../asset/C/C011_toktogi/3D/versions/restore_map.json)의 `archive:`와 `current:`를 구분해 작업 사본에 복원하고 해시를 확인한다.
- v2.3은 개별 2,374셀의 크기·Sprite 색/Alpha·데이터 패스 A=255를 확인했다. [픽셀 기록](../../../../../../Documents/ChatGPT/2DGP/pipeline_production_review/pixel_audit.json)과 [내장 텍스트 해시](../../../../../../Documents/ChatGPT/2DGP/pipeline_production_review/embedded_inventory.json)를 보존한다. A의 통합 Blend와 B의 통합 작업본 SHA256이 같으며 최종 출력기는 `EXPORT_PLAYABLE→TOKTOGI_SURFACE→SPRITE_PNG`다. 초기 외부 `export_playable.py`의 외곽색/전체 양자화를 그대로 재사용하지 않는다.
- 기존 [07·08 접촉 기록](../../asset/C/C011_toktogi/2D/integrated-r5/geometry_validation.json)의 r5 07 교차 후보 30쌍, [Z 연속 자세 기록](../../asset/C/C011_toktogi/3D/framework-r4/spin_interkey_validation.json)의 r4 왼쪽 키 사이 가시 교차 19자세는 잔여 검토 범위다. 후보를 실제 관통으로 단정하지 않는다. DEC-06 양산은 보류다.
- 06–07은 플레이 손질, 08·관계 관찰은 검수용이다. 수영·부력·수면 도약·산란·관계 의존 플레이는 제외한다. 개구리밥/연꽃잎 고체 발판 환경은 [StageLevel](StageLevel.md)의 신규 범위다. 공중제비 회전량·시간은 각색이다. [행동 근거](reference/toktogi_movement.md) · [현행 상태](game-design/toktogi_state_machine.md#atlas-states)
- C011의 프로젝트 `sheet/`는 README만 있다. B의 [Blender 6면 시트](../../../../../../Documents/ChatGPT/2DGP/toktogi_modeling_sheet_20261117/blender_reference/sheet.png)·[GPT Image 시트](../../../../../../Documents/ChatGPT/2DGP/toktogi_modeling_sheet_20261117/gpt_image/sheet.png)·[프롬프트](../../../../../../Documents/ChatGPT/2DGP/toktogi_modeling_sheet_20261117/gpt_image_prompts.txt)는 기존 bind-pose 렌더의 후속 참조 자료다. 최초 모델이 GPT 시트 기반이었다는 근거로 소급하지 않는다. B 링크는 작업 폴더에 의존하므로 인계 시 관련 근거를 보관하고 상대 링크를 갱신한다.
- 아래 명령은 **프로젝트 전체의 작업 사본 루트**에서 실행한다. 패커는 스크립트 옆 ZIP·잠금을 갱신한다. 보조 ZIP·잠금은 [제작 절차](../../asset/C/C011_toktogi/3D/framework-r4/README.md)에 따라 먼저 함께 배치하며 HTML은 두 번들과 MotionSet을 사용한다.

```powershell
python toktogi/prototype/pack_assets.py asset/C/C011_toktogi/2D/integrated-r5
python toktogi/prototype/build_motion_preview.py asset/C/C011_toktogi/2D/integrated-r5 asset/C/C011_toktogi/ToktogiMotionPreview.html
python toktogi/prototype/main.py --verify
```

- 명령은 현행 Pygame 도구 기준이며 이번에 실행하지 않았다. Pico2D·F2 Normal 비교·Bloom은 [Rebuild](Rebuild.md)의 별도 구현 대상이다. v2.3 Blender MCP 재개방은 120초 시간 초과였으며 저장 파일 정적 추출·PNG·문서 링크를 검증했다. 모델/출력 재생성·포즈/재생·실기 성능의 신규 합격 기록은 아니다.
- 신규 캐릭터는 [C211 외형 명세](../../asset/C/C211_spider_paradosa/document/spider_pardosa_model.md)처럼 정확한 대상·다리 수·크기 기준을 먼저 정하고 시트·리그·모션·로더를 연결한다. C011의 128px·37본·기관·예산·지원 방향을 자동 승계하지 않는다.
